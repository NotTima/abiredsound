# ABI RedSound

Веб-приложение для игры **Arena Breakout: Infinite** — распознаёт предметы торговца (Field Merchant) по звуку и показывает, что в грузе, шансы на редкие предметы и окупаемость.

*by Euthanasia // Timaa*

## Как это работает

1. Открываешь сайт в **Chrome** или **Firefox** на ПК
2. Вводишь ключ доступа (по умолчанию: `ARS-67`, `ARS-12` или `REDSOUND`)
3. Нажимаешь «Слушать игру» → выбираешь окно игры (или системный аудиовыход в Firefox при включённом `Stealth: Только звук`)
4. Сайт захватывает аудио → даунсэмплинг → NCC-корреляция по 76 шаблонам pickup/drop (ускорение через `engine.wasm`)
5. Определяет предмет → показывает шансы и окупаемость по выбранной карте

## Быстрый старт (локально)

```bash
# Вариант 1: через Node.js сервер
npm start
# или: node server.js

# Вариант 2: как чистая статика (как на GitHub Pages)
python3 -m http.server 8080 --directory site

# Открыть в Firefox или Chrome:
# http://localhost:8080
```

> **Поддержка Firefox**: Полная! В Firefox при нажатии «Слушать игру» выбирается окно игры, а если браузер не отдаёт системный звук напрямую через захват экрана, автоматически запросится доступ к аудиоустройству (`Monitor of Built-in Audio` на Linux / `Stereo Mix` на Windows).

## Что исправлено и улучшено

- **Все 189 иконок предметов на месте**: 10 недостающих PNG перенесены из первой версии (`abiredsound`), для остальных 157 сгенерированы тактические SVG-иконки с цветовой кодировкой редкости и размером слота + добавлен глобальный fallback.
- **Рабочий `engine.wasm`**: собран валидный WebAssembly-модуль с `fft` (Radix-2/4 Cooley-Tukey), убрана ошибка загрузки пустого wasm-файла.
- **Простой ключ и чистый UX/UI**: убраны лишние заглушки серверных функций (отчёты, синхронизация с телефоном, лента чужих находок, фейковая админка с локальной статистикой и MOTD), улучшен контраст и вёрстка. Вместо шуточного «Сканера удачи» добавлен **Справочник предметов (189 позиций)** с поиском, фильтром по редкости и прослушиванием звука.
- **Готовность к GitHub Pages**: все пути сделаны относительными, добавлен `js/gh-pages-shim.js` (перенаправляет `/api/catalog` на статический `api/catalog` и глушит серверные эндпоинты без 404-ошибок в консоли), добавлен `.nojekyll` и workflow для деплоя.

## Как лучше всего выложить на GitHub Pages

Самый удобный и правильный способ для этого проекта — **через встроенный GitHub Actions workflow** (файл `.github/workflows/pages.yml` уже добавлен), потому что само приложение лежит в подпапке `site/`, а не в корне репозитория.

### Пошаговая инструкция:

1. **Создай репозиторий на GitHub** (можно приватный, если не хочешь светить код, но для приватных репозиториев GitHub Pages доступен на тарифе Pro; для бесплатного аккаунта проще сделать публичный репозиторий или использовать Cloudflare Pages).
2. **Залей папку `abiproject` в ветку `main`**:
   ```bash
   cd abiproject
   git init
   git add .
   git commit -m "ABI RedSound ready for GitHub Pages"
   git branch -M main
   git remote add origin https://github.com/<твой-логин>/<имя-репозитория>.git
   git push -u origin main
   ```
3. **Включи GitHub Pages через Actions**:
   - Открой репозиторий на GitHub → **Settings** → **Pages**.
   - В разделе **Build and deployment → Source** выбери **GitHub Actions** (не «Deploy from a branch»).
4. **Готово!**
   - Перейди во вкладку **Actions** — workflow `Deploy ABI RedSound to GitHub Pages` автоматически соберёт и опубликует содержимое папки `site/`.
   - Через ~30 секунд сайт будет доступен по адресу `https://<твой-логин>.github.io/<имя-репозитория>/`.
   - Скидывай ссылку друзьям и ключ входа (`ARS-67`, `ARS-12` или `REDSOUND` — ключи можно поменять в `site/js/auth-admin.js` в `VALID_KEYS`).

> **Важно**: GitHub Pages работает по **HTTPS**, а для захвата аудио (`getDisplayMedia` / `getUserMedia`) в браузере обязательно нужен именно HTTPS — поэтому на GitHub Pages всё будет работать из коробки!
